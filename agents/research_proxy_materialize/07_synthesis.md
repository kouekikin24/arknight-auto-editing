## 二、六份报告的共识与反驳

**共识（印证方案）**：
1. 「难解码源→落盘易播中间体」是全行业正统（Resolve 五通道、Premiere 双轨、FCP 转码、Nuke/Cinelerra 后台渲染）。
2. 1080p60 H.264 长 GOP 是所有 NLE 的公认最弱场景（官方点名+社区实证）——我们自研解码器恰好补这一环。
3. 我方 CRF14 代理体积 2.26GB/h，比行业帧内代理（40.5~187GB/h）小 **18~83 倍**。
4. 开源三家无一做到「1080p60 长 GOP 裸实时流畅」——我们的痛是真实行业痛。
5. 「按导出节奏触发物化 + 短GOP 导出级代理兼预览」**无先例**（新颖性确认，agent4 §5 检索）。

**反驳与修订（全部采纳）**：
1. 【Premiere/06】H.264 长 GOP 代理会重蹈 seek 覆辙 → **代理编码强制短 GOP≤30（体积仅 +10-20%，FCP 报告公式）+ 帧索引 sidecar**；顺带治 200ms 掉帧 burst 100% 可感知的问题（06 §帧率）。
2. 【04】触发语义单一会反噬 → **物化触发=playhead 前向预物化 + 全量后台双驱动**。
3. 【04】段级失效重编反噬 → **追加式物化**（新段追加、旧段不失效），避免 Resolve「剪一下缓存作废」的最痛。
4. 【01】音频缺位 → 代理携带源音轨（现状无音频链路，预留）。
5. 【06】「高倍速保节奏」行业视为伪需求、1x 档节奏一致=弱刚需+差异化 → 承诺口径收敛为 **1x 档严格=导出节奏**（物化按构造天然满足全档位，宣传以 1x 为准）。
6. 【05】导出分三形态：**草稿导出（smart-cut，每切点 ≤2s 边界重编码≈近零代价；SMC 开源先例 CRF14 同档）/ 标准导出（全量编码保留区间）/ 代理直出（需 CRF14 视觉无损验收）**。

## 三、路线图修订（基于调研）

1. **Phase-1.5（新增，半天）**：dsvc seek 锚点改「≤目标帧最近关键帧」——深 seek 从 >60s → ~1-2s（P0 体验缺陷，不等二级）。
2. **Phase-2（正解，2-3 天，吸收全部修订）**：物化代理=短GOP CRF14 + 帧索引 + playhead/全量双驱动触发 + 追加式物化 + 段级增量 + 暂停真源帧 + 携带音轨占位。
3. **Phase-3（可选）**：导出三形态（smart-cut 草稿 / 标准 / 代理直出）。
4. **维持否决**：NVDEC（吞吐不敌软解）、W 路线（同天花板）、原始帧全预解（带宽超 SSD）。
